# Market simulator

Part of [market-sim](../README.md). A small, deterministic **multi-country market feed simulator**. It streams newline-delimited JSON
(`trade` and `price` messages) over TCP, so you can practise real-time ingestion
(Kafka / Event Hubs / Spark Structured Streaming) without a real data source.

Everything here is **simulated**: companies and tickers are fictional, prices are generated by a
random process, and start prices and FX levels are illustrative, not live market data.

## Quick start

```bash
# Docker
docker build -t market-sim .
docker run --rm -p 1337:1337 market-sim --interval-min 400 --interval-max 800

# or plain Python 3.10+ (standard library only)
python -m simulator --interval-min 400 --interval-max 800

# look at the stream
nc localhost 1337
```

No network? Print messages instead of serving them: `python -m simulator --mode stdout --max-messages 1000`.

## Messages

One JSON object per line. Timestamps are **UTC, second resolution**.

```json
{"type":"price","data":{"instrument_id":"…","price":112.6578,"date":"2025-01-06T09:03:48Z"}}
{"type":"trade","data":{"trade_id":"…","instrument_id":"…","price":23.001,"volume":82241,"side":"BUY","currency":"GBP","date":"2025-01-06T09:01:00Z"}}
```

| Field | Notes |
|---|---|
| `type` | `price` (a quote) or `trade` (an execution) |
| `instrument_id` | joins to `data/instruments.csv` |
| `trade_id` | unique per trade (UUID) |
| `price` | equities 4 decimals; FX 5 decimals (3 for JPY pairs) |
| `volume` | integer shares, 100 to 100,000 |
| `side` | `BUY` or `SELL` |
| `currency` | the instrument's trading currency (same as `instruments.csv`) |
| `date` | event time, UTC |

## Reference data (`data/instruments.csv`)

33 instruments: 30 equities (5 each in the Netherlands, Germany, France, United States, United Kingdom, Japan) and
3 FX pairs. The Netherlands, Germany and France all trade in EUR, so country and currency are different dimensions (three countries share one currency). Columns: `instrument_id, long_name, short_name, country, sector, industry, exchange, type, currency`.

FX is quoted as **units of the second currency per 1 unit of the first**:
`EUR/USD` = USD per EUR, `GBP/USD` = USD per GBP, `USD/JPY` = JPY per USD.
There is no direct rate to euro for GBP or JPY, so converting to EUR takes a chain:

```
GBP -> EUR :  amount * GBP/USD / EUR/USD
JPY -> EUR :  amount / USD/JPY / EUR/USD
```

`data/sim_params.csv` holds the simulation parameters (start price, annual volatility, beta, liquidity weight).

## What makes it behave like a market

- **Trading sessions** (UTC, Mon to Fri): Tokyo 00:00 to 06:00, Amsterdam and London 08:00 to 16:30,
  New York 14:30 to 21:00, FX around the clock. Weekends are skipped. Daylight saving is not modelled.
- **Follow-the-sun activity**: message volume rises with the liquidity that is open, so it peaks
  when Europe and New York overlap and is thin when only FX trades.
- **Correlated prices**: each equity has a `beta` to a common market factor plus its own noise;
  `annual_vol` is the instrument's total volatility.
- **Fast clock**: simulated time runs faster than real time (`--sim-seconds-per-message`).
- **Late data**: by default about 0.5% of messages are stamped slightly earlier than the previous
  ones (still inside their own session). Good for practising watermarks.
- **FX has quotes only**, no trades. A trade's currency always matches its instrument.

## Options

| Option | Default | Meaning |
|---|---|---|
| `--interval-min / --interval-max` | 400 / 800 | real delay between messages (ms) |
| `--port` | 1337 | TCP port |
| `--seed` | 42 | same seed gives the same stream |
| `--start` | `2025-01-06T00:00:00Z` | simulated start (use a Monday, UTC) |
| `--sim-seconds-per-message` | 30 | mean simulated gap between messages |
| `--trade-ratio` | 0.55 | share of trades while equities are open |
| `--late-prob` | 0.005 | share of out-of-order timestamps |
| `--duplicate-prob` | 0 | share of messages sent twice |
| `--bad-prob` | 0.01 | share of corrupted messages (null or negative price, zero volume, unknown instrument, bad side, garbage line) |
| `--max-messages` | 0 (endless) | stop after N messages |
| `--mode` | `tcp` | `stdout` prints instead of serving |

Duplicates are **off by default**; about 1% of messages are corrupted by default. Turn duplicates on
to test deduplication, and set `--bad-prob 0` for a perfectly clean stream. The generator never repeats a line by accident, so any
duplicate you see came from `--duplicate-prob`.

Each TCP client gets its own stream starting from the beginning, and the same seed gives
every client the same messages. Reconnecting replays the stream.

## Tests

```bash
pip install pytest
python -m pytest -q
```

The tests cover the message schema, determinism, trading sessions and weekends, late/duplicate/bad
message switches, price sanity, volatility calibration and the intraday activity profile.

## Limitations

- Illustrative start prices and FX levels; not live data.
- One common market factor; no sectors, news events, holidays or crashes.
- No order book. Trades are executed near the mid price with a small spread.
- Trade volume does not depend on price or on liquidity beyond the instrument weights.
